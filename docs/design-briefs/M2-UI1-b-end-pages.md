## 0. 现状（简报依据）

- 前端为 pnpm workspace：`apps/admin`（Element Plus 校管端）+ `apps/campus`（Vant 4，C 端壳）+ `packages/api-client`（手写 fetch 客户端，含 auth 会话/401/403 统一处理）。
- admin 已有 7 个认证相关页面（登录/忘记密码/重置/强制改密/MFA 绑定/安全设置/首页骨架）+ 路由守卫（静默恢复会话、首登改密门禁、MFA 门禁）。
- 测试基线：前端 32 单测（Vitest）+ 28 mock E2E（Playwright）+ 12 全栈 E2E；不回归是硬约束。
- 后端能力全部就绪（M2-ORG01~06 + M1 看板 overview），**本点原则上零后端改动**（例外见 D1）。

## 1. 目标与验收

校管登录后可完成日常组织管理全流程，无需 SQL：

1. 人员管理：教师/学生列表（掩码邮箱、身份证掩码）、建档（可选身份证号）、学生转班（留级/跳级）。
2. 身份证受控查看（人员管理页内弹窗，非独立页）：有 `school.personnel.sensitive.read` 才可见入口；弹窗填理由（≥10 字）→ 明文；关闭即清除，不落前端存储。
3. 班级/课程/任教：建班（入学年份+当前年级，同届重名 409 提示）、指派班主任/辅导员、排课。
4. 部门树：树形展示、建/改名/停用/删除（409 提示原因）。
5. 批量导入：上传（≤10MB csv/xlsx）→ 进度轮询 → 错误行列表（含身份证掩码）→ 失败行重试。
6. 学年流转：向导式（映射 → dry_run 预览核对入学年份 → 确认执行）；幂等键前端生成；409 重复提交友好提示。
7. **TD-141 收口**：菜单与按钮按 `/auth/me` 的 permissions 渲染（无权限入口不可见）；E2E 钉"无权限入口不可见 + 直连 URL 仍由后端 403"。

**不含**（D1 决策）：角色↔权限配置后台、角色重置出厂、MFA 管理员重置（拆 M2-UI2）；**看板与权限账号移出本点**（实现前核实：看板属 M6 DASH-01、权限账号接口未交付——简报初版基于 design.md 计划表误判，已修正）。

## 2. 候选方案

### 决策 D1：范围切分（需用户拍板）

- **方案 A（推荐）：本点=纯 UI 消费既有 API，零后端改动**；TD-141 随本点收口。角色权限配置后台（TD-137+TD-150 标记列迁移+`school.role.manage` 接口）、角色重置（TD-143）、MFA 重置（TD-126）**拆为独立功能点 M2-UI2**（三者都需要新后端接口+高风险确认，塞进来会让本点膨胀到难以审查）。
- 方案 B：一个功能点全包（页面 + 三组后端接口）——单点过大（估 3000+ 行），审查与回归面都差，不推荐。

### 决策 D2：API 层形态

- **方案 A（推荐）：沿用手写模式按域扩展** `packages/api-client/src/`（org.ts / imports.ts / dashboard.ts 等，类型对齐后端响应模型，测试随域补）——与现有 auth.ts 同构，本点不引入新工具链。
- 方案 B：引入 OpenAPI 代码生成（openapi-typescript，FastAPI 已有 /openapi.json）——长期更优（api-client 注释已预告），但本点页面多、引入生成链路会放大变更面；**登记 TD，M3 知识库接口多时再切换**。

### 决策 D3：布局与导航（TD-141 落点）

- **方案 A（推荐）：Element Plus 标准后台布局**（侧边菜单+顶栏身份区），菜单项/按钮按 permissions 渲染；无权限路由直接 403 页（后端是真实边界，前端只做体验）。
- 方案 B：自由布局——无收益，不推荐。

### 决策 D4：列表分页控件

- **方案 A（推荐）：按接口语义分两型**——cursor 接口（teachers/students/classes/assignments）用"上一页/下一页+加载更多"简化控件（游标透传）；offset 接口（personnel、导入错误行）用标准页码。**不伪造页码**（keyset 语义下伪造页码会出现重复/漏行）。
- 方案 B：全部伪造成页码——与 TD-070 的 keyset 语义冲突，不推荐。

### 决策 D5：身份证受控查看交互

- **方案 A（推荐）：列表行"查看"按钮（无权限不渲染）→ 弹窗填理由（≥10 字，前端预校验）→ 展示明文 + 掩码对照；组件卸载/关闭即清空明文状态；不写 localStorage/sessionStorage**。后端已有 no-store；前端补"明文不出现在 DOM 之外的任何持久层"。
- 方案 B：独立页面跳转——多一跳路由，理由随 URL 风险（D3-A 已确认理由放请求体的初衷），不推荐。

### 决策 D6：学年流转交互

- **方案 A（推荐）：三步向导**（① 选年级映射/归档年级，可按入学年份过滤 → ② dry_run 预览表：逐班列出将从 X→Y，人工核对 → ③ 确认执行：二次确认弹窗，幂等键=前端 uuid4，409 重复提交提示"已执行过"）。执行成功展示影响计数。
- 方案 B：单表单一把梭——不可逆批量操作无预览，与后端 dry_run 设计初衷相悖，不推荐。

### 决策 D7：E2E 策略

- **方案 A（推荐）：mock E2E 为主 + 关键链路补全栈**——每页 1~2 条主链路（约 14 条 mock）；导入成功链路、学年流转链路各补 1 条全栈 E2E（真实后端，价值最高的两条）。
- 方案 B：全部全栈 E2E——运行时长不可接受（现有 12 条已 ~10 分钟级），不推荐。

D1-A（纯 UI + TD-141，角色/MFA 管理拆 M2-UI2）、D2-A（手写域模块；OpenAPI codegen 登记 TD）、D3-A、D4-A、D5-A、D6-A、D7-A。
是否需要改 spec/design：design.md §5.4 增 B 端页面清单一节（回写随提交）。

## 4. 实现顺序（TDD：先 api-client 域模块测试，后组件）

1. api-client 域模块：org（classes/courses/assignments/departments/teachers/students/transfer/rollover）/ imports / dashboard / permission-accounts——每模块先写接口测试（mock fetch），再实现。
2. 布局与菜单（TD-141）：permissions 渲染 + 403 页 + 路由守卫扩展。
3. 人员管理（列表/建档/编辑/转班）→ 身份证受控查看 → 班级/课程/任教 → 部门树 → 导入 → 学年流转 → 看板 → 权限账号。
4. TD-141 用例 + 全栈 E2E 两条 + 文档回写。

红→绿清单（关键）：
- [ ] api-client：cursor 分页透传、409/422 错误到提示文案的映射（ORG_CONFLICT/CLASS_ARCHIVED/ID_CARD_*）
- [ ] 受控查看：理由 <10 字禁发请求；明文仅存于组件 ref
- [ ] 学年流转：dry_run 结果逐班渲染；幂等键一次生成不重复；409 提示
- [ ] 导入：进度轮询（1s 间隔，完成即停）；错误行展示身份证掩码不出现明文
- [ ] TD-141：无 sensitive.read 无查看按钮；无 org.manage 无流转菜单

## 2. 决策卡（2026-11-14 用户拍板，全按推荐）

### 卡 D0 · 拆分 → **A：2 PR**（KB-10A 后端整块 / KB-10B 前端整块）
后端面内聚（derive 依赖 edits 表与管线分支）；前端沿 A/B 先例。KB-10A 预估单测 +15 / 集成 +14 / 业务 +3。

### 卡 D1 · 向量复用 → **A：Qdrant 源 collection 直接复制，不建 `kb_embedding_cache` 表**
scroll 源 collection 按 chunk_id 取向量 → 写新 collection；嵌入调用次数 = 改动块数天然满足。落选缓存表（design :227）：派生必有单源 collection，通用缓存无第二消费者——偏离登记 TD-319 同款流程（新 TD）。sparse 派生版本重算不缓存（本地免费 + IDF 必须按派生语料，TD-312 口径）。

### 卡 D2 · derive = 确认即构建 → **A：单动作**
超管 confirm 派生 → 版本行（version_no=max+1、`derivation_type='chunk_edit'`、parent_version_id、复制源 audiences + confirmed 列〔D3〕）→ BUILD_QUEUED；`_claim` 扩：`derivation_type='chunk_edit'` 构建跳过文档状态检查（文档可 PUBLISHED）；管线 branch 跳过 PARSING/CHUNKING：COPY 全部分块（改动块更新 text/hash/token/char/is_human_edited=true/edited_by/at）→ EMBED 仅改动块 → Qdrant 复制未改块向量 → INDEX → VALIDATE → READY。失败重试不影响源版本与 alias。

### 卡 D3 · ACL 继承 → **A：复制源 audiences 行 + 保留已确认态（state-machines :85）**
spec :308 与 :85 矛盾随本简报批注对齐（:85 为 KB-05 期修订的更新口径；「需重新确认」留给真重传新版本语义）。

### 卡 D4 · 编辑记录 → **A：submitted/confirmed/discarded 三态**
POST edits 直接 submitted；derive 时提交态 confirmed + derived_version_id 关联，未纳入派生的提交 discarded；GET diff 列表回提交记录。

### 卡 D5 · 内容校验 → **A：轻量结构检查**

### 卡 D6 · 前端（KB-10B）→ **A：编辑按钮 + 对话框（409 处理）+ diff/派生确认区（confirm 码渲染）+ is_human_edited tag**；全栈链扩「编辑→派生→嵌入计数→发布→旧会话不漂移」段。

### 附带

## 3. 契约（KB-10A）

**迁移**（1 个）：`kb_document_versions` 加 `parent_version_id UUID NULL` + `derivation_type VARCHAR(24) NULL`（CHECK ∈ initial/chunk_edit）；新表 `kb_document_audiences` 同款 FORCE RLS 的 `kb_chunk_edits`（id/tenant_id/source_version_id FK/chunk_id FK/before_hash/after_hash/new_content TEXT/edited_by FK/reason/status CHECK 三态/derived_version_id NULL/created_at；唯一 `(source_version_id, chunk_id, status)` 部分唯一 WHERE status='submitted'——同块至多一个提交态）；downgrade 数据前提：无。

**API**（`app/api/school_kb.py` + `app/kb/chunk_edit.py` 新服务模块 + `build_task.py` 派生分支）：

| 端点 | 权限 | 语义 |
|---|---|---|
| `POST /school/kb/chunks/{chunk_id}/edits` | `school.kb.chunk.edit` | `{new_content, reason, base_hash}`；校验 chunk 存在（跨租/范围外 404 同文）→ base_hash ≠ 当前 chunk_hash → 409 `CHUNK_CONFLICT`（乐观锁；审计 denied）→ 内容校验 422 `CHUNK_CONTENT_INVALID`（非空/长度/围栏配对/表格完整）→ 写 kb_chunk_edits submitted + 审计 `school.kb.chunk.edited`（含 reason、chunk_id、before/after hash）→ 201 |
| `GET /school/kb/document-versions/{id}/chunk-edits` | `school.kb.view` | 该版本全部提交记录（含 status/derived_version_id/diff 摘要） |
| `POST /school/kb/document-versions/{id}/derive` | `school.kb.chunk.confirm` | 源版本需 READY/TEST_PASSED/PUBLISHED/APPROVED（状态机 :84-85）；无 submitted 编辑 → 409 `DERIVE_NO_EDITS`；已确认 → 409 `CHUNK_EDIT_STATE`；生成派生版本（version_no=max+1、derivation_type、parent_version_id）+ 复制源 audiences（confirmed 列同源）+ 提交态 confirmed + 其余 discarded + 审计 `school.kb.chunk.derive_confirmed`（确认人/编辑人/改动块数）→ BUILD_QUEUED → 201 回派生版本 id |

**构建**：`build_task` 派生分支（`derivation_type='chunk_edit'`）：跳 PARSING/CHUNKING；COPY：从源版本 kb_chunks 全量复制（改动块按 kb_chunk_edits.new_content 更新 + is_human_edited/edited_by/edited_at + chunk_hash 重算 + token/char 重算）写入新版本；EMBED：仅改动块调 embedder（**嵌入调用次数 = 改动块数**）；未改块向量 `scroll` 源 collection 按 chunk_id 复制；INDEX/VALIDATE/READY 同既有；sparse 重算（派生语料 IDF）。

**payload**：`build_payload` 加 `is_human_edited: bool`（12 字段）+ 分块详情/列表回包透出；KB-03B payload 断言测试同步。

**ACL 继承**：derive 事务内复制源版本 kb_document_audiences 行（audience_type/audience_id 同值，created_by=确认人）+ `acl_confirmed_by/at` 复制源值（沿用已确认态——D3-A）。

## 8. KB-10A 实现注记（2026-11-14，实现期偏离/细化登记）

1. **派生版本状态机**：派生版本行 status='APPROVED'（走既有 APPROVED→READY 状态机与 _claim 门禁），不新增 DERIVED 状态名——派生语义由 `derivation_type='chunk_edit'` 列承载；`_claim` 豁免：派生构建跳过文档状态检查（源文档可 PUBLISHED 在线）且文档状态不跟随 BUILDING/READY（spec :327 不影响源）。
2. **派生 chunk 行 id = 新 uuid4**（非复用源行 id——kb_chunks.id 全局唯一）：未改块向量从源 collection retrieve 后写入新 point id；测试向量对齐按 payload text_hash（未改块 hash 不变→向量逐值相等断言 dense）。
3. **sparse 重算不复制**（TD-312 口径）：派生语料 IDF 变化 → sparse 向量逐值与源不同是**设计正确**；测试向量复用断言只比 dense。
4. **父/子 hash 同形边界**：单段章节的父块与子块文本一致 → chunk_hash 相同；BS-M3-11 向量断言只遍历 child 行（只索子块，父块不在 Qdrant；parent 行会误入未改块分支）。
5. **derive_gate 优先级修正**：已确认派生（CHUNK_EDIT_STATE）优先于提交数（DERIVE_NO_EDITS）——重复派生检测不被提交数掩盖（复审语义）。
6. **拒绝审计独立事务**：409 `CHUNK_CONFLICT` 两处（乐观锁 + 已有 submitted）审计走独立短事务（KB-02 先例：主事务 raise 回滚主事务内审计写入）。
7. **派生管线 client 生命周期**：retrieve 段与 INDEX/VALIDATE 段各自新建 AsyncQdrantClient（retrieve 段 close 后 INDEX 段重建——复用已 close 的 client 报「client has been closed」，实测踩坑）。
8. **嵌入计数断言形态**：FakeEmbedder 子类计数 embedded_texts；派生管线 EMBED 输入 = embed_input_text(title, section, new_text)（与既有管线同构），计数 = 改动子块数。

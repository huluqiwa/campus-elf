## 0. 背景与缺口（为什么现在做）

用户指出（2026-10-25）：现行班级模型把年级做进业务唯一键 `(租户, 年级, 班名)`，且全系统没有"学年流转"概念——**所有学校每年夏季开学都要整体升一个年级**（不分中小学/大学）。现行模型在第二个开学季即撞墙：全校班级年级标签失真、"按年级圈人"（KB-09）筛不出真实年级、修正需要一场无功能支撑的大规模改数，且"高二 1 班"若已存在会撞唯一约束。同时班级缺人可读的**编号**，大学同年级不同专业同名班无法建档。

时点：B 端页面未做、无生产数据，是模型修订成本最低的窗口；M3 KB-09 按年级圈人依赖此语义。

## 1. 目标与验收

1. 班级增业务编号 `code`（租户内唯一、建班必填），作为跨学年稳定身份；唯一键 `(年级, 班名)` 移除，同年级同名班可建。
2. 年级降为**当前态属性**：学年流转操作批量刷新（中间年级 +1），编号/学生/指派/范围行不变。
3. 学年流转：毕业年级班级与学生批量转"毕业"（账号禁登录、档案与历史保留）；可选"流转时重分班"（学生重指派）；留级/跳级 = 个体学生重指派到目标年级班。
4. 导入定位班级支持 `班级编号` 列（优先）；`年级+班名` 兼容，多行命中 → 结构化歧义错误行。
5. 流转全量审计、幂等（重复提交不二次执行）；dry-run 预览影响面。

验收：spec ORG-06 四条（同名班可建 / 流转不变量 / 留级跟班 / 编号定位导入）。

## 2. 候选方案

### 决策 D1：班级编号与唯一键

- **方案 A（推荐）：`code` 必填、租户内唯一；移除 `(grade,name)` 唯一约束**。编号格式由校方自定（K-12 建议 `C2025-01` 届号式——升学时编号不变；大学 `计算机2401` 式）。优点：语义清晰、编号即身份、升学不换号；缺点：存量测试造数全部要补编号（机械）。
- 方案 B：`code` 可空、保留 `(grade,name)` 唯一——大学同名班依然建不了，只解决一半，不推荐。

### 决策 D2：年级存储还是派生

- **方案 A（推荐）：存储当前态，流转批量刷新**。支持留级/跳级/中途插班（个体重指派即可），实现直白。缺点：流转是一次批量 UPDATE（全校班级几十~几百行，量级可控）。
- 方案 B：年级 = 入学学年派生（当前日期计算）——零刷新，但留级/跳级/重读需要逐生覆盖字段，特例反而更复杂；且"当前学年"本身需要一个学年锚点配置。不推荐。

### 决策 D3：毕业学生状态机（需确认——涉及登录状态）

现行 `users.status IN ('active','locked','disabled','deleted')`，students 表无状态列。

- **方案 A（推荐）：`users.status` 增 `'graduated'`（CHECK 迁移扩值）+ `students` 增 `status` 列（`active`/`graduated`）**。登录层已只放行 active（现有行为不变）；人员列表默认过滤毕业（提供查询参数包含）；"被停用"与"已毕业"语义可区分，档案永久保留。
- 方案 B：复用 `disabled`（不加值）——改动最小，但"校管停用"与"自然毕业"混为一谈，恢复激活即语义矛盾，不推荐。

### 决策 D4：流转操作形态

- **方案 A（推荐）：单端点 `POST /school/academic-year/rollover`，单事务，幂等键 + dry_run 预览**。请求体：`{"target_year_label": "2026", "reshuffle": false, "dry_run": true}`；幂等键防重复提交（同键重复请求返回首次结果）；dry_run 返回将刷新/毕业的班级与学生计数明细，前端确认后真执行。审计记操作者/参数/影响计数。
- 方案 B：落批次表的三步向导（预览批次→确认→执行）——可追溯性更好但 MVP 过重，审计+幂等键已覆盖核心诉求；批次表延后（见 TD）。

### 范围内子决策（随简报确认）

- **重分班**：`reshuffle=true` 时请求体附"新年级班 ← 学生编号清单"映射；未覆盖的学生默认跟原班（升年级），不丢人。
- **教师任教关系**：流转**不动** `teacher_class_courses`（跨学年任教是学校人事行为，由校管自行调整；班主任/辅导员指派随班保留）。
- **权限**：流转与班级维护同权限 `school.org.manage`；不做独立权限码。
- **编号列兼容**：学生导入若同时提供编号与年级+班名且互相矛盾 → 错误行 `CLASS_CONFLICT`。

## 3. 选择结论

D1-A、D2-A、D4-A 建议采纳；D3 建议采纳 A（唯一需要用户明确点头的点：毕业生账号进"不可登录但可区分"状态）。

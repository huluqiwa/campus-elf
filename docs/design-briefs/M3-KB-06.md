## 0. 现状（2026-11-10，均已在代码核实）

## 2. 决策卡（2026-11-10 用户拍板，全按推荐）

### 卡 1 · A/B 拆分 → **A：KB-06A 后端 + KB-06B 前端**
沿用 KB-04A/B、KB-05/05B 节奏：06A 一个短 PR（端点 + 仓储 + 测试），06B 一个短 PR（api-client + 抽屉分块区 + mock E2E）。后端契约先定，前端 mock 判据有唯一锚点。

### 卡 2 · 端点形状 → **A：版本域 3 端点 + `parent_id` 筛选参数**
`GET /versions/{version_id}/chunks`（列表）、`GET /chunks/{chunk_id}`（详情 + 父/子引用）、`GET /versions/{version_id}/chunks/stats`（统计）。列表扁平按 `chunk_index` 升序；`parent_id` 参数保留「按父展开」的树呈现能力，不锁死 06B 的 UI 形态。不选「父块为主行」模型（子块才是被索引主体，父行模型下「搜索只返回匹配块」语义别扭）。

### 卡 3 · 分页 → **A：游标 keyset `(chunk_index ASC, id ASC)`**
与 design §5.1 / TD-070 cursor 口径一致；`chunk_index` 版本内唯一，次序稳定。**实现口径**：共享 `list_cursor` 硬编码 `(created_at, id)` 次序，本点**不改共享分页函数**（爆炸半径为零），在 chunk 读模块内用 `repository.base_query()` 注入租户谓词后内联实现 keyset 谓词与 `(chunk_index, id)` 游标编解码；游标解码失败沿用既有 `INVALID_CURSOR` 400 语义。

### 卡 4 · 搜索筛选 → **A：纯 DB contains，父/子块都参与匹配**
- `q`：strip 后空→忽略；`ILIKE '%q%'` 匹配 `text` 列，`%`/`_`/`\` 显式转义（纯函数，可单测）；父块与子块都参与匹配、结果带 `chunk_type` 标签——表格/代码全文在父块里，只搜子块会让「表格/代码未被拆坏」在搜索结果里不可见。
- `section_path`：**精确匹配**（简报显式化：候选「精确/前缀」中本期取精确；值来源 = stats 的 sections 清单，UI 下拉天然精确语义）；子树（前缀）筛选登记 TD。
- 语义检索是 KB-07，本点不混入。

### 卡 5 · 统计聚合 → **A：后端聚合端点**
单事务内聚合 SQL（`GROUP BY (chunk_type, embedding_status, section_path)` 单条 + Python 汇总），返回扁平统计对象；分页下前端永远看不到全集，统计只能在服务端算。**统计不随筛选参数变化**（per-version 固定口径，简报显式化）。

### 卡 6 · 渲染净化 + 大文档 → **A：纯文本渲染 + 游标分页**
- 分块文本（租户上传物，天然不可信）一律纯文本/代码样式渲染，**不引入 `v-html`**（不渲染即无 XSS 面）；渲染源用 `text_markdown`（表格竖线/代码围栏原样可读，保真承载「表格/代码未被拆坏」）。
- 大文档靠服务端游标分页满足 spec「大文档分页/虚拟滚动」（措辞为「/」）；虚拟滚动与 markdown 净化渲染均登记 TD，有真实需求再做。
- 响应同时返回 `text` 与 `text_markdown`（页 ≤100 行成本可忽略，留渲染灵活性、避免未来契约变更）。

### 卡 7 · 租户隔离与数据范围（固定口径）
1. 端点挂 `school.kb.view_chunks`（`require_permission(..., realm="tenant")`；realm 校验先行，平台主体 403）。
2. 版本解析走 scope 过滤仓储（`KbDocumentVersion`，`owner_attr="created_by"`）——不可见/跨租/不存在一律 404，与 KB-01A 读语义、KB-05 的 404 对齐口径一致。
3. chunk 查询走 `TenantScopedRepository + ScopeBypass`（kb_chunks 无归属列；版本已按范围校验，分块按版本归属访问），查询恒带 `document_version_id ==` 谓词。
4. 详情端点链式校验：chunk（租户谓词 get）→ 其 `document_version_id` 经 scope 过滤版本仓储复核 → 不可见即 404（不泄露存在性）。
5. 直连租户表 = CI 守卫护栏预期拦截（KB-05 首跑红先例，不绕）。

## 4. 契约（KB-06A 端点规格）

服务端实现放**新模块 `backend/app/kb/chunk_read.py`**（读侧独立、避免 service.py ~2900 行继续膨胀；假设显式化，审查时对照）。响应模型放 `school_kb.py`（与其他端点同址）。

### 4.1 `GET /api/v1/school/kb/versions/{version_id}/chunks`

| 参数 | 类型 | 说明 |
|---|---|---|
| `version_id` | path UUID | 版本必须对当前主体可见（scope 过滤），否则 404 `VERSION_NOT_FOUND` |
| `limit` | int，1–100，默认 20 | |
| `cursor` | str \| None | `(chunk_index, id)` 游标 |
| `q` | str \| None | strip 后 ≤200（超长 422，FastAPI `max_length`）；空→忽略；`ILIKE` 转义 |
| `section_path` | str \| None | 精确匹配 |
| `chunk_type` | `"parent" \| "child"` \| None | Query 枚举，非法 422 |
| `parent_id` | UUID \| None | 按父展开 |

响应：`PageResponse[KbChunkResponse]`；`KbChunkResponse` 字段：`id, chunk_type, chunk_index, parent_id, text, text_markdown, section_path, page_start, page_end, token_count, char_count, embedding_status, created_at`（KB-10 三列不出现）。

### 4.2 `GET /api/v1/school/kb/chunks/{chunk_id}`

响应 `KbChunkDetailResponse = KbChunkResponse + document_version_id + parent: {id, chunk_index} | None + children: list[{id, chunk_index}]`（children 按 `chunk_index` 升序；父块返回子块清单，子块返回空清单）。404 链见卡 7-4。

### 4.3 `GET /api/v1/school/kb/versions/{version_id}/chunks/stats`

响应 `KbChunkStatsResponse`：`total_chunks, parent_count, child_count, embedding_status: {pending, ready, failed}, total_tokens, total_chars, section_count, sections: list[{section_path, chunk_count}]`（按 chunk_count 降序、该版本全量去重章节，文档结构有界）。版本不可见 404 同 4.1。

**对简报的两处如实偏离（独立审查确认后登记）：**

1. **业务场景未按 §5 第 6 步「夹具直插构建后状态」，改跑真实全链**（HTTP 上传 dev-skip → 提交 → 审批 → 构建 → worker READY → 分块断言；审查 Minor 3）。覆盖更强（真实管线产出真实分块，权限/404 全走真链路），代价每条 ~10s 真实构建；integration 文件聚焦读侧机制（种子经真实构建落库），两层互补。
2. **`q` 的 `max_length=200` 度量 strip 前原始值**（审查 Minor 2）：与 §4.1「strip 后 ≤200」字面不符；方向保守（超长空白填充 422）无安全影响；FastAPI Query 下 strip-then-validate 需自定义依赖、成本不值——契约按 raw 长度登记（家族先例 `_TitleStr` 是先 strip 再量，两处口径不同已知晓，不做统一）。

**实现中自查修掉的问题：**

- 共享 `list_cursor` keyset 硬编码 `(created_at DESC, id DESC)`（repository.py:196），分块需要 `(chunk_index ASC, id ASC)` → 按卡 3 在 chunk_read 内联实现，共享分页函数零改动。
- CI 守卫规避：统计聚合若写 `select(KbChunk.chunk_type, …)` 会触 `test_only_exempted_modules_touch_tenant_tables` 静态正则 → 按 KB-05 同款 `base_query().subquery()` + `select(subquery.c.*)` 形态，守卫用例本地跑绿。
- 业务场景首跑 2 failed：上传后停 `UPLOADED`（测试栈无 ClamAV、arq 无 worker，扫描入队后无人消费）→ env 补 `DEV_SKIP_FILE_SCAN=true`（与 BS-M3-05 同款，仅测试编排；`Settings` 生产硬拒不变）后 2 passed。

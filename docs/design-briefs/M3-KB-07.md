## 0. 现状（2026-11-11，均已在代码核实）

**检索实现层：**

- **RRF 在 Qdrant 服务端融合，逐路分数不透出**：`indexer.py:262-305` `search_points` 用 `query_points` 双 `Prefetch`（dense/sparse 各 `limit=top_k*2`）+ `FusionQuery(fusion=RRF)`，返回 `[{"chunk_id","score","payload"}]`，score **只有融合分**。要逐路分数必须旁路补查（卡 1A 的依据）。
- **查询构造（KB-04A 口径，检索测试须镜像）**：dense 输入 = `embed_input_text(document_title, section_path=None, chunk_text=query)`（`embedding.py:167`，标题前缀拼接，与构建侧同构）；sparse 输入 = `version_sparse_weights([query])[0]`（`test_task.py:266`）。
- **sparse IDF 语料不对称（既有 MVP 缺口，本点如实镜像、不顺手修）**：构建侧 `build_task.py:616` 用全版本语料算 IDF；查询侧（test_task.py:266）语料=单条 query → IDF 常数化，sparse 信号弱于真实 BM25。修正归 M4（新 TD 候选，§6）。
- **批量测试运行（KB-04A）**：`test_task.py:250-308` 逐 case `search_points(top_k=10)` 融合检索，`metrics_json.cases[]` 只有 `pass/hit/expected_count/retrieved_count/latency_ms/is_adversarial`，无分数、无 rerank。
- **rerank 生产代码为零**：无适配器、config 无 `tei_rerank_url`（`config.py:174` 注释预留「rerank 实例是检索侧（KB-07）」）；**compose 已有 `tei-rerank` 服务**（`deploy/docker-compose.yml:202-229`：TEI cpu-1.9.4 + `BAAI/bge-reranker-v2-m3`（revision 953dc6f6）+ `--auto-truncate` + `--max-client-batch-size 8`，host 端口 `127.0.0.1:8082`，卷 `tei_models`）。TD-056：CPU 8 候选 p50≈11.7s（`docs/benchmarks-m0.md`）。
- **版本状态机**（`status.py:22-50`）：collection 在 INDEXING 创建、构建 READY 后存在；`READY/TESTING/TEST_PASSED/TEST_FAILED/PUBLISHED/OFFLINE/DELETED` 均有索引可检；`FAILED/QUEUED/BUILDING/审批前状态` 无有效索引。

**权限与租户（固定口径，沿 KB-06A 卡 7 先例）：**

## 2. 决策卡（2026-11-11 用户拍板，全按推荐）

### 卡 0 · 范围 → **A：KB-07 = 单 query 检索测试诊断端点 + 展示面**
版本切换 MVP 归 KB-08（TD-305 前置）；TD-310 阶段 1 独立小点；TD-311 维持现状；LLM+Ragas 归 M4。ACL 三参数契约预留、设值即 422（§3）。

### 卡 1 · 逐路分数透出形态 → **A：三查询旁路**
融合 RRF 查询**原样不动**（生产/沙箱检索语义零漂移，既有测试集结果不变）；同一 dense/sparse 输入旁路各跑一次 dense-only、sparse-only 单路查询（limit = pool×2），app 侧按 `chunk_id` 合并出各路分数与该路排名。落选：B app 侧重算 RRF（改变候选池与融合语义，存量 expected_chunk_ids 对账漂移）；C 只显示命中标记（spec 要求分数数值）。

### 卡 2 · rerank 在 CPU 预算下的选型 → **A：诊断端点内同步 rerank（opt-in），TEI 适配器 + fake 端口**
- 新增 `RerankPort`（Protocol，fake 注入）+ `TEIReranker`（TEI `/rerank` 适配器，`--auto-truncate` 已由服务端保证截断）+ config `tei_rerank_url`（默认 `http://127.0.0.1:8082` 对齐 compose）/`tei_rerank_timeout_seconds`（默认 60，诊断级，非 §7.5 的 300ms）/`kb_retrieval_test_rerank_pool`（默认 20）。
- **rerank 池 = 融合查询扩量结果**：`with_rerank=true` 时融合查询 limit=pool(20)，rerank 后按分数重排，最终引用 = 重排后前 `top_k`；`with_rerank=false`（默认）时融合查询 limit=`top_k`，最终引用 = 融合 top_k。比卡文「默认 8」的细化：池独立成配置（默认 20），重排有「裁剪」语义（对齐 §7.5 top50→top10 的精神），CPU 成本 ≈20 对 ×1.46s ≈ 29s，opt-in + UI 明示耗时。
- **失败/超时永不 5xx**：降级为融合序 + `rerank_status="skipped"|"failed"`（§7.5「超时跳过」同哲学）；嵌入/检索基础设施故障 → 502（KbError `http_status`）。
- 落选：B 本点不接 rerank（spec :296 明文含 rerank，验收缺口）；C 异步 rerank（诊断面过度设计）。

### 卡 3 · rerank 与 KB-04A 批量运行的关系 → **A：批量 run 维持现状（无 rerank、无逐路分数）**
既有测试集结果零漂移；「批量 run ≠ 生产 chat 管线（有 rerank 漏斗）」差异登记 TD（§6），M4 chat 管线定型时统一评估是否升级 run 语义。

### 卡 4 · UI 联动 → **A：检索测试面板嵌在分块子视图内**
`chunksView` 顶部加检索测试区（query 输入 + top_k + with_rerank 开关 + 运行按钮 + 结果表）；结果行「查看分块」复用既有详情子面板父子导航。依据：权限目录本就耦合两能力（catalog.py:78），同码同视图、不新增导航层级。落选：B 独立子视图（多一层状态、跳转丢上下文）；C 挂 `school.kb.test` 测试区块（权限码不符，假门禁风险）。

### 卡 5 · A/B 拆分 → **A：KB-07A 后端 + KB-07B 前端**
沿 KB-04A/B、KB-06A/B 节奏：07A 一个短 PR（端口/适配器/编排/端点 + 测试），07B 一个短 PR（api-client + 面板 + mock E2E + 全栈断言）。契约先定，mock 判据有唯一锚点。

## 3. 契约（KB-07A 端点规格）

服务端实现放**新模块 `backend/app/kb/retrieval_test.py`**（读侧独立，`chunk_read.py` 同款理由，避免 service.py 膨胀）；rerank 端口放**新模块 `backend/app/kb/rerank.py`**；单路查询帮手加在 `indexer.py`。响应模型放 `school_kb.py`（同址先例）。

### 3.1 `POST /api/v1/school/kb/versions/{version_id}/retrieval-test`

请求 `KbRetrievalTestRequest`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `query` | str | **raw 码点 ≤300**（`max_length=300`，KB-06A 偏离 2 口径：按 strip 前度量）；strip 后非空（全空白 422）。前端预检用 `codePointLength`（KB-06B m-1 教训入库） |
| `top_k` | int，1–20，默认 10 | 最终引用条数（对齐 KB-04A top_k=10） |
| `with_rerank` | bool，默认 **false** | CPU 重排 opt-in；UI 明示「约 10~30s」 |
| `as_user_id` / `as_audiences` / `ignore_acl` | 与 design §5.7 同形，默认 null/null/false | **KB-09 预留**：任一非默认值 → 422 `RETRIEVAL_TEST_ACL_UNAVAILABLE`「ACL 视角检索未开放」（防静默忽略的 fail-closed 语义） |

响应 `KbRetrievalTestResponse`：

```
{
  "version_id", "query", "top_k", "with_rerank",
  "rerank_status": "applied" | "skipped" | "failed" | "disabled",
  "latency_ms", "pool_size",
  "results": [KbRetrievalTestResultRow]   // 按 final_rank 升序
}
```

`KbRetrievalTestResultRow`：

| 字段 | 说明 |
|---|---|
| `chunk_id, chunk_index, chunk_type, section_path, page_start, page_end` | 来自 PG chunk 行回查（Qdrant payload 无 chunk_index/正文） |
| `text_preview` | `text` 前 200 码点（完整内容经既有分块详情端点取） |
| `dense` / `sparse` | `{score, rank} \| None`——None = 该路 pool×2 内未召回；rank 为该路 1-based 排名 |
| `rrf_score` | Qdrant 服务端 RRF 融合分 |
| `rerank_score` | float \| None（未启用/降级为 None） |
| `final_rank` | 1..pool_size；`with_rerank=false` 或降级 = 融合序 |
| `is_final_reference` | `final_rank <= top_k` |

**错误链**：403（realm/缺码，require_permission 既有语义）→ 404 `VERSION_NOT_FOUND`「文档版本不存在」（不存在/跨租/范围外同文）→ 409 `RETRIEVAL_TEST_NOT_INDEXED`「该版本暂无可检索的索引」（版本状态 ∉ {READY, TESTING, TEST_PASSED, TEST_FAILED, PUBLISHED, OFFLINE, DELETED}，实现时对齐 `status.py` 常量）→ 422（query/top_k/ACL 预留）→ 502 `RETRIEVAL_TEST_EMBED_FAILED` / `RETRIEVAL_TEST_SEARCH_FAILED`（基础设施故障，KbError `http_status` 显式给）。

**固定口径**：查询输入镜像 KB-04A（`embed_input_text(title, None, query)` + `version_sparse_weights([query])[0]`）；PG 回查走 `TenantScopedRepository(KbChunk) + ScopeBypass(reason="检索测试：按版本取分块展示")` 且恒带 `document_version_id ==` 谓词；索引有而 PG 缺行的分块跳过（构建双对账已保证一致，防御性容错，简报显式化）；不落库、无新迁移、无运行时审计（读路径先例）、日志零 query 明文。

## 4. 实现顺序（TDD 红→绿；KB-07A → KB-07B 各一个 PR）

# 实现前设计简报（design-briefs/）

> 规则：每个功能点或里程碑单元在写任何代码前，先落盘一份简报；代码审查以简报为对照。

## 命名

`<里程碑或功能点ID>-<简短描述>.md`，例如 `M0-E-compatibility.md`、`KB-03-build-progress.md`。

## 必填结构

见 `_template.md`：

1. 目标与验收引用
2. 候选方案（≥2，含默认方案）与优缺点/风险
3. 选择结论与理由
4. 是否修改 spec/design
5. 实现顺序与 TDD 测试清单
6. 测试策略（单元/集成/业务场景/E2E/评估/性能）
7. 预判技术债（登记 tech-debt.md）
8. 高风险确认项（认证/租户/权限/状态机/删除/发布/加密/AI 护栏）

## 与审查的关系

- 审查先回答“实现是否符合本简报”；
- 简报未覆盖的新方案，进入 tech-debt.md 并给处置；
- 简报本身有误，先改简报再改代码。

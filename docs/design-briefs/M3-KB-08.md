## 0. 现状（2026-11-12，均已在代码核实）

**切换动作已交付（KB-05），KB-08 动作面零新增：**

- `rollback_version`（`service.py:2622`）＝把活跃发布切到**任意 PUBLISHED 目标**（D2-A）：守卫链＝目标版本 scope 链 404 `VERSION_NOT_FOUND` → 非发布态 409 `KB_NOT_PUBLISHED` → 索引记录/点数复核 → 无指针 409 `KB_NO_ACTIVE_PUBLISH`（:2683）→ 目标即活跃 409 `KB_ROLLBACK_TARGET_IS_ACTIVE`（:2686）；当前活跃版本**保持 PUBLISHED**（蓝绿共存）。
- `active_publish`（`service.py:2272`）：内部解析函数，返回 `(version_id, collection) | None`，**kb_publish_aliases 库行是事实来源**；无端点（TD-305）。
- 发布指针读法：`_publish_alias_repository`（`service.py:2238`，无 scope——别名表无归属列）+ `document_id` 谓词；写侧串行化走 `_publish_alias_row`（FOR UPDATE，:2258）。

**详情回包无活跃语义：**

- `GET /documents/{document_id}` → `KbDocumentResponse`（`school_kb.py:120-130`，含 `current_version`，无 active 字段）；⚠️ 该模型同时被列表页（:261）与上传回包（`KbUploadResponse.documents`，:138）复用——契约必须避免列表 N+1 与 null 歧义（卡 1 的依据）。
- 详情链 404：`get_document`（`service.py:545-561`）scope 过滤仓储 + `DOCUMENT_NOT_FOUND`（跨租/范围外/不存在同文不泄露）；`get_document` 在 app 内**仅此一个调用方**（`school_kb.py:274`），无测试直调——改造影响面收敛。

**前端会话内活跃记忆（KB-05B D2-A 补偿，待服真化）：**

- `KbDocumentDrawer.vue`：`activeVersionId` ref（:127）只来自本会话动作响应（publish/rollback 成功 ：286/:313；offline/delete 且 `was_active` 置 null ：336/:363；关抽屉重置 ：607）——刷新/多标签后未知。
- `rollbackTargets`（`kb-logic.ts:310-313`）＝PUBLISHED − 已知活跃；选到活跃版本吃后端 409 兜底。

**多版本可达性与种子：**

- 产品流上传恒建新文档单版本（`service.py:893` 附近），M3 无生成第二版本的产品入口；多版本文档由测试种子造——`seed_two_published_versions`（`tests/support/kb_publish_seed.py:198`）经 HTTP 发布 v1→v2，返回 `(doc_id, v1, v2)`，可直接作验收链的 Given。
- 测试账号：`KB_PUBLISHER`（publish/delete/view，无 view_chunks）、`KB_CHUNK_VIEWER`（`view_chunks`，school 范围，`kb_env.py:163-170`）、`KB_B_PUBLISHER`/`KB_B_CHUNK_VIEWER`（租户 B）。

## 2. 决策卡（2026-11-12 用户拍板，全按推荐）

### 卡 0 · MVP 范围 → **A：TD-305 契约 + 活跃标识服真化 + 「切换→查看分块」验收链**
spec 版本切换唯一验收＝:302；切换动作（KB-05 回滚）与按版本定域的分块子视图（KB-06B）均已交付，本点真实增量＝活跃版本对前端服真化（TD-305）+ 该验收的端到端断言。不做 diff（二期）/子视图切换器/新建版本入口。

### 卡 1 · TD-305 契约形态 → **A：详情回包专属扩展模型**
`GET /documents/{id}` 回包升级为 `KbDocumentDetailResponse = KbDocumentResponse + active_version_id: UUID | None`；list/upload 的 `KbDocumentResponse` **不动**。语义：`active_version_id` = kb_publish_aliases 该文档行的 version_id（与 `active_publish` 同源）；无活跃发布（未发布/下线/软删已撤指针）= null。落选：B 独立 `GET .../active` 端点（多一次请求、「无活跃」404 语义与文档 404 混淆、TD-305 登记方向就是详情回包加字段）；C 可选字段塞全模型（列表/上传回包 null 歧义、逐行真值 N+1）。权限口径：字段随 `school.kb.view` 详情链下发、**不设新码**（管理信息非敏感，写动作仍各挂 publish/delete 码）；跨租/范围外 404 照旧。

### 卡 2 · 动作面/展示面边界 → **A：动作面零新增，展示面补真值**
动作面＝既有 `POST /versions/{target_version_id}/rollback`（即「版本切换」），不新增写端点、不改状态机。展示面＝版本行/版本状态列加「当前活跃」标识（服务端真值）+ 分块子视图维持按版本定域 + 验收链补断言。UI 文案可加「切换活跃版本」说明但不改动作门禁（mock 不比后端严——187g-C Blocker 先例）。

### 卡 3 · 与 KB-05B 会话内记忆的关系 → **A：服务端初始化 + 动作响应就地更新并存**
抽屉打开时 `activeVersionId` 用详情回包 `active_version_id` 初始化（刷新/多标签不再未知）；会话内动作响应继续就地更新（现行为保留，不加请求）；**409 `KB_ROLLBACK_TARGET_IS_ACTIVE` 兜底保留**（另一端在两次动作之间切换过 → 本地 stale，兜底因此仍必要）。

### 卡 4 · A/B 拆分 → **A：KB-08A 后端 + KB-08B 前端，各一 PR**
沿 KB-04A/B、06A/B、07A/B 先例：契约先定，mock 判据有唯一锚点。

## 3. 契约（KB-08A 端点规格）

实现落点：`backend/app/kb/service.py`（视图/服务）+ `backend/app/api/school_kb.py`（模型/路由）；无新迁移、无新权限码、无审计（读路径先例，KB-06A 同口径）。

### 3.1 `GET /api/v1/school/kb/documents/{document_id}`（详情回包升级）

- `response_model` 换为 **`KbDocumentDetailResponse(KbDocumentResponse)`**，新增字段 `active_version_id: UUID | None`。
- 语义：kb_publish_aliases 中该文档行的 `version_id`；无行（未发布/已下线/活跃版本已软删——撤指针）= `null`；**fail-closed**：调用方（前端/M4）不得把 null 解读为「任选版本」。
- 列表 `GET /documents` 与上传回包**不含**该字段（基模型不动）：列表/上传/PUT 元数据三处均构造自基模型；上传回包另有 `KbUploadResponse.documents: list[KbDocumentResponse]` 的类型构造结构性保证。契约边界测试在**根锚点**断言基模型 `model_fields` 不含该字段（审查 M-2 落法）。
- 服务层：`get_document` → **`get_document_detail`**，返回新冻结 dataclass `DocumentDetailView(document: DocumentView, active_version_id: UUID | None)`；alias 读与文档读**同一事务**（一次额外 SELECT；READ COMMITTED 下两者间存在并发发布竞态窗口，消费侧由 409 兜底承担——审查 M-3 口径修正）；抽取 `_active_alias_row` 助手（命名与写路径 `_publish_alias_row` FOR UPDATE 成对区分），`active_publish` 改为复用（自身会话包装与返回 `(version_id, collection)` 不变，行为零漂移——既有 KB-05 集成/业务用例全数回归背书）。
- 错误链不变：403（realm/缺码）→ 404 `DOCUMENT_NOT_FOUND`「文档不存在」（不存在/跨租/范围外同文不泄露存在性；404 body 无 active 字段）。
- 跨租断言既有链回归 + 本点补一条详情跨租 404（§4）。

### 3.2 前端消费（KB-08B，只消费不动后端）

- api-client `kb.ts`：`getDocument` 返回类型升级 `KbDocumentDetail`（`KbDocument` + `active_version_id: string | null`）；列表/上传类型不动。
- `KbDocumentDrawer.vue`：打开/刷新抽屉时 `activeVersionId` 用详情回包初始化；publish/rollback/offline/delete 成功响应就地更新保留（:286/:313/:336/:363 行为不变）；409 兜底保留。
- 版本表状态列/版本行加「当前活跃」tag：`versions.find(v => v.id === activeVersionId)`；会话内动作后随 ref 实时更新。
- `rollbackTargets` 签名不变，排除基准由「会话记忆」升级为「服务端真值 + 会话更新」。

## 8. 实现注记（对 §2/§4 决策的如实偏离/细化，独立审查后登记）

1. **红→绿的承担面**：4 条 `active_version_id` 语义用例按预期 `KeyError` 红（未实现时详情回包无该键）；「列表契约边界」与「跨租详情 404」两条在实现前即绿——它们钉的是既有行为（列表本就不带该字段、404 链本就同文），作为实现后的回归守卫，非红→绿证据。
2. **业务场景的「不混入」双保险**：种子两版本若用默认同 markdown，内容级断言无从谈起——本点显式传互异 markdown（`V1-ONLY-MARKER`/`V2-ONLY-MARKER` 各自成段），断言做**结构级**（两版本 chunk_id 交集为空）+ **内容级**（v1 分块含 V1 标记不含 V2 标记，反向同理）双保险。
3. **读/写指针行助手命名区分**：新增 `_active_alias_row`（无锁读）与既有 `_publish_alias_row`（FOR UPDATE，发布/回滚写路径串行化）成对——语义不同（读不改锁行为），不复用同一个避免给读路径误加锁。
4. **`get_document` 更名 `get_document_detail`**：返回类型从 `DocumentView` 变为 `DocumentDetailView`（document + active_version_id）；app 内唯一调用方是详情端点、无测试直调（已核实），更名影响面收敛；不保留旧名兼容垫片（内部函数无外部契约）。
5. **`_document_detail_response` 复用 `_document_response`**：`KbDocumentDetailResponse(**_document_response(view).model_dump(), active_version_id=...)`，基模型字段不重复手写——两处字段漂移风险归一。

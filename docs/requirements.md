## 0. 角色与工作模式（最高优先级）

1. **先计划，后编码**：未获明确确认前，禁止生成生产代码、禁止创建业务工程文件（澄清问答与文档草稿除外）。
2. **协作流程 = Spec → SDD → TDD**：需求对齐 → 文档落盘 → 测试驱动开发，顺序执行，不可跳步。
3. **Spec 是唯一事实来源**：实现中发现需求矛盾或遗漏，必须先提出修改 Spec 并经确认，不得静默自行决定。
4. **逐项澄清**：所有【待确认】项必须逐条给出建议并等待确认，不得默认采纳。
5. **单点推进**：一次只开发一个功能点，完成后必须汇报；禁止并行开发或一次性铺开全部实现。
6. **假设显式化**：任何默认假设（技术选型、数据结构、边界行为）必须显式列出并征求确认。

### 0.1 已确认的流程增强

- **业务场景测试**：每个功能点不仅要有代码层测试，还必须通过业务场景测试，断言最终业务输出与副作用。
- **代码审查**：业务场景测试通过后做独立代码审查；有问题必须修复并重新跑业务场景与全量测试，复审通过后才能提交、汇报、进入下一个功能点。
- **DoD**：功能点 = 单元/集成/业务场景/E2E（如涉及）全绿 + 业务输出断言 + AI 评估（如涉及）+ 代码审查通过 + 问题修复复测 + 文档同步 + 原子提交 + 汇报。

## 1. 项目概述

### 1.1 产品定位

面向高校的多租户 SaaS 平台，为学校提供 AI 陪伴、校园知识库、校务审批、消息通知、轻社交与心理关怀辅助能力。核心用户：SaaS 平台工作人员、校方超级管理员、校方权限账号、教师、学生。

差异化卖点：多租户强隔离、知识库审批构建测试发布热更新闭环、统一审批与全量审计、校方可运营的 AI 陪伴与校务辅助。

### 1.2 分层模型

- **SaaS 平台后台**：租户审核、平台配置、知识库定制化、运营审核、平台消息、审计。
- **B 端校方管理后台**：本校人员、权限、知识库、审批、消息、公告（二期）、告警（二期）、运营。
- **C 端**：AI 陪伴、个人知识库（二期）、课表（二期）、任务（二期）、消息、校园墙（二期）、请假等。

该分层是 B 端配置、功能优先级、开发排序的共同依据。

### 1.3 分期范围

#### 第一期（MVP，本期开发）

多租户注册、学校编号、三端登录、RBAC + 数据范围、人员导入、B 端人员管理、知识库上传→审批→构建→测试→发布→热更新闭环、C 端 AI 对话、学校知识库问答、引用来源、流式输出、反馈、请假申请与审批、账号删除审批与 5 天保留期状态机、统一审批中心、消息中心、SaaS 后台租户审核开关、基础模型配置、统一审计日志、租户隔离、内容安全基础能力。

**MVP 额外纳入（本轮确认）**：
- 校方基础运营看板 + C 端反馈查看/标记/答复/简单统计。
- 知识库构建进度实时查看（SSE + 轮询兜底）。
- 知识库分块预览（列表/详情/统计/搜索/检索测试/版本切换）。
- 文档查阅人群 ACL：为文档版本配置可查阅人群（部门/角色/班级/年级/课程/指定人/全体），未配置即禁止构建/发布，AI 检索按登录身份强制过滤（K4，2026-10-21 确认）。
- 分块编辑与派生重建：校方可编辑子块文本，经校方超管确认后生成派生版本，仅重嵌改动块（K5，2026-10-21 确认）。
- C 端答案 SSE 流式 + 脱敏后的思考步骤/摘要开关。
- 账号删除/撤销登录权限双入口。

**MVP 不做**：MCP/SKILLS 创作市场、盲盒、词频热度榜、自动心理诊断、学生创作工具、完整心理告警闭环、校园墙、积分任务、个人知识库、个人课表、长期记忆、技能中心、皮肤中心完整流程、知识库定制化完整流程、计费、公告、微信小程序、AI 写操作、定制人设、C 端已读、版本间分块 diff、完整视图监控/趋势分析/反馈导出。

#### 后续拓展（本期不实现，仅架构预留）

- **二期**：个人知识库、个人课表、长期记忆、历史会话、任务中心、积分、基础皮肤兑换、校园墙基础版、心理告警人工复核处置闭环、知识库定制化、技能中心基础版、皮肤中心、公告审批、皮肤审批、账号删除审批完整流程。
- **三期**：MCP/SKILLS 市场、学生/教师创作中心、工具沙箱、盲盒与概率公示、词频热度榜、高级知识库定制化、租户配额成本运营计费。

**阶段冲突（待确认）**：
- 词频热度榜：2.2 写“视图监控二期”，1.3/3.4 写“三期”。
- 盲盒：2.2 皮肤中心二期提到盲盒概率，1.3/3.4 把“盲盒与概率公示”放在三期。
- 账号删除完整流程：MVP 已有核心 5 天状态机，二期又列“完整流程”；当前按“MVP 核心 + 二期补齐申诉/冻结/通知/合规证明”处理。
- 基础公告：8.2 的 MVP 建议包含“基础公告”，但 2.1/2.2 把公告与公告审批列为二期；已确认整体推迟。

### 1.4 产品闭环

学校注册审核开通 → 校方导入人员授权 → 知识库上传审批构建测试发布 → C 端 AI 问答引用反馈 → 请假/消息/审批流转 → 审计与运营监控。

### 1.5 已确认的重大技术/产品修订

1. **Python 3.13.x**（不是 3.12）。
2. **Qdrant** 作为向量库（不是 pgvector）。
3. **MinerU 4.0.12**；原 `pipeline/vlm/hybrid` 是 3.x 概念，4.0 用 `flash/basic/standard/advanced` 四档取代；按 Standard→Basic→Flash 自动降级。
4. **C 端移动端 H5**（Vue 3 + Vant 4），不做微信小程序 MVP。
5. **Langfuse Server 4.63.0 + Python SDK 5.0.2，生产独立主机自托管**，开发 optional；默认元数据+哈希，内容采集按场景开启；Git 是生产 prompt 唯一事实来源。
6. **知识库审批是构建硬门禁**：按单个文档版本审批，通过后才能解析/切块/嵌入/索引/构建。
7. **账号删除双入口**：用户自助 + 管理员撤权，共用 5 天只读状态机。
8. **C 端已读二期、B 端已读 MVP**；清空当前会话 MVP、定制人设二期。
9. **代码审查 + 业务场景测试** 为每个功能点的强制门禁。
10. **校方看板 + 反馈查看** 纳入 MVP；最终阶段创作中心教师和学生均可参与。

## 2. 功能需求

### 2.1 用户侧 / C 端

#### 2.1.1 C 端六类检查项

1. **意图/输入范围**
   - 支持学校知识库问答、公告查阅总结（二期）、个人知识库问答（二期）、识图解析（二期）、课表/任务/消息/请假等业务入口、负面情绪检测告警（二期，人工复核，不自动诊断）、同一需求多意图识别一次作答。
   - 意图能力来源为“已发布知识库版本 + 已授权技能 + 用户开关 + 业务模块可用状态”的动态并集；禁止硬编码意图清单或分词 if 判断。
   - **已确认**：MVP 使用能力注册表 + LLM 结构化路由；`RouteResult.intents[]` 支持多意图一次作答；MVP 只读问答 + 业务入口导航，不执行写操作。

2. **流式输出与 SSE**
   - AI 答复必须支持流式输出与 SSE；首字响应目标 ≤3s；思考内容实时展示，支持开关与脱敏；引用来源随答复展示。
   - **已确认**：快路径首答案 token P95≤3s；ReAct 路径首个 SSE 状态事件 P95≤3s、首答案 token P95≤5s；两套指标分开统计。
   - SSE 事件：`meta`、`step`、`tool_call`、`tool_result`、`reasoning_summary`、`delta`、`citation`、`done`、`error`。
   - 思考内容只展示脱敏后的步骤/摘要，不展示原始 chain-of-thought；不返回 reasoning 时只显示状态，禁止伪造。

3. **会话管理**
   - MVP 支持新会话、历史入口、同一会话近 10 轮短期记忆并总结前文。
   - 二期支持历史会话延续/删除/清空/编辑标题、长期记忆开关/查看/编辑/删除、会话保存为个人知识库。
   - **已确认**：MVP 增加“清空当前会话记录”；定制人设二期。

4. **能力缺失兜底**
   - 不得回复“无法理解”；必须给出可执行替代路径：切换知识库范围、联系校方管理员、提交反馈、展示可用功能入口。
   - **已确认**：多意图逐项兜底，不能因一个意图失败而整题拒答。

5. **转人工/升级路径**
   - 本系统无普通人工客服转接；心理告警（二期）由授权辅导员/班主任人工复核与处置，提供申诉/更正渠道；审批类问题进入审批中心与消息中心；能力缺失时引导提交反馈或联系校方管理员。

6. **写操作安全机制**
   - 写操作包括：请假提交/撤回、消息发送、知识库上传/构建/发布/下线、审批操作、账号删除申请、反馈提交、二期任务领取/积分兑换/校园墙发布等。
   - 所有写操作必须服务端鉴权、租户上下文校验、幂等键 + 唯一约束、状态机校验、审计留痕。
   - **已确认**：MVP AI 不执行写操作；写操作全部通过前端表单/按钮与显式确认。

#### 2.1.2 C 端功能点

- **登录**：选择学生/教师身份；学生学校编号 + 学号 + 密码，教师学校编号 + 员工号 + 密码；随机初始密码、首次登录强制改密、密码找回、失败锁定、可选 MFA。
  - 已确认：JWT access 15m + refresh 7d 轮换；bcrypt cost 12；最小 10 位、至少 3 类字符、最大 128、禁止含学号/工号、最近 5 次历史；5 次/15 分钟锁定；登出/改密/删除撤销 refresh token 家族；员工邮件重置、学生由校管重置并审计。
- **AI 陪伴精灵交互**：
  - 初始轻量 3D 蓝色机器人待机形象（低端机降级 Lottie/静态图）。
  - 入口：历史会话、新会话、清空当前会话、反馈；添加技能（二期）、创作（三期）、换肤（二期）、定制人设（二期）、记忆开关（二期）、个人知识库（二期）、课表（二期）。
  - 学校知识库问答并展示引用来源；对 AI 答复反馈；流式输出；思考摘要；Prompt 注入防护、内容安全、引用校验、超时降级。
- **个人知识库二期**：上传 PDF/Markdown/DOCX/PPT/TXT，单文件 ≤30M，填写文档名、标签、描述；停用/删除、修改/新增、查看构建进度；仅本人可用，默认不共享，可审计。
- **个人课表二期**：学生/教师编辑课表，支持选修课差异、导入/导出与冲突提示。
- **任务中心二期**：教师发布判断题/选择题任务到所任课班级；学生领取完成获得积分；积分兑换皮肤/盲盒；积分流水、防刷、兑换记录审计；盲盒概率公示。
- **创作中心三期**：学生/教师制作 MCP/SKILLS/精灵形象/皮肤，提交审批并提供提示词与测试用例；工具类创作必须走沙箱与安全测试；审批通过后按范围上架。
- **消息中心 MVP**：接收/发送消息到对方账号；接收审批、系统通知；B 端已读 MVP，C 端已读/举报/拉黑二期。
  - 已确认：MVP 仅系统/审批通知 + 师生 1:1 文本消息；不做学生互发、群聊、附件、举报/拉黑。
- **校园墙二期**：发布文章 50–500 字可带标签；失物招领/寻物帖 ≤300 字；点赞、评论、回复，发布者可删除；敏感词、图片审核、举报、人工复审；“吃瓜/吐槽”标签内容仅进入聚合脱敏词频统计。
- **请假 MVP**：选择班主任/辅导员，填写缘由 ≥50 字、姓名、班级、学号、天数，提交审批；状态草稿→待审批→通过/拒绝；草稿可编辑/删除，待审批可撤回，通过后不可编辑仅在线预览；审批记录含审批人、时间、理由。
  - 已确认：MVP 仅学生请假；审批在 B 端审批中心完成；班主任/辅导员需授予 B 端审批权限。
- **账号删除 MVP**：
  - 用户自助申请 + 管理员撤销登录权限双入口；共用状态机。
  - 审批通过后 5 天保留期内可登录，但只能申诉或只读，禁止一切写操作。
  - 冻结 = 暂停删除倒计时、转人工复核；账号仍只读。
  - 到期删除/匿名化，生成删除证明；拒绝恢复原状态；唯一超管由 SaaS 复核。

### 2.2 管理侧 / 运营后台

#### 2.2.1 SaaS 平台后台

- **学校注册与资质审核**
  - 学校提交学校名、地址、校领导信息、学校邮箱、资质凭证。
  - 开发/测试环境可通过配置开关跳过资质凭证与审核；生产默认关闭跳过；生产不得默认放行。
  - 审核通过生成学校编号、超级管理员账号、随机初始密码并发送至学校邮箱；审核记录含审核人、时间、结果、理由、凭证快照。
  - 学校编号全局唯一作为租户标识。
- **SaaS 工作人员登录**
  - 账号由平台初始化，不开放界面注册；密码策略、首次登录改密、可选 MFA；权限按角色分配，操作留审计。
  - 已确认：MFA 功能可选，生产可对 SaaS 员工/超管强制。
- **审核**
  - 学校资质通过/拒绝，拒绝需理由；审核记录可查询、导出、审计。
- **消息中心**
  - 接收校方定制化请求、意见反馈、审批通知；支持回复、已读状态、模板消息、失败重试。
  - 平台与校方消息通道隔离，跨租消息记录来源租户。
- **知识库定制优化二期**
  - 接收校方定制优化请求，记录文档、理由、测试集、FAQ；支持参数配置、代码级优化发布流程、FAQ 优先答复；版本化与蓝绿发布、回滚、校方验收记录。
  - 已确认：定制化场景启用 Langfuse dataset/experiment，校方提供测试集和 FAQ。
- **配置中心**
  - 配置 LLM/VLM/嵌入/重排序模型 api-key、base-url、model-name，密钥加密存储。
  - 配置全局与租户级切块策略、检索策略、限流与配额；二期配置 MCP/SKILLS 允许清单。
  - 数据库连接走环境变量/密钥管理，不进业务后台。
  - 所有配置变更需审批或双人确认，记录变更前后值、操作人、时间。
  - 已确认：生产至少两个平台特权账号；只有一个时走 break-glass（原因+审计+事后复核）。

#### 2.2.2 B 端校方管理后台

- **登录与账号**
  - 超管使用学校编号、账号、密码登录；初次登录随机初始密码并强制改密；修改密码、密码策略、登录失败锁定；超管拥有本校全部权限，权限账号按权限矩阵授权。
- **人员管理**
  - 创建/移除权限账号，支持多权限分配。
  - 录入教师员工号、姓名、年龄、性别、职位、任教班级、任教课程、身份证号等；身份证号加密存储并掩码展示。
  - 录入学生学号、姓名、班级、性别、班主任、辅导员、身份证号等；脱敏规则同上。
  - 支持手动录入与 CSV/XLSX 异步导入，提供错误行报告、重复策略、失败重试。
  - 录入前可通过校方配置的 MCP/接口核查人员信息；核查接口支持超时、降级、人工确认。
    - 已确认：MCP 推迟二期；MVP 只保留可选 HTTP 核查适配器，默认关闭。

## 3. 非功能需求（强制）

### 3.1 性能

1. 核心 API P95≤500ms（不含 AI 生成）；AI 首字响应≤3s；SSE 首 token P95≤3s，自请求到达网关起算；知识库发布热切换无中断。
   - 已确认：快路径首答案 token P95≤3s；ReAct 路径首个 SSE 状态事件 P95≤3s、首答案 token P95≤5s；两套指标分开统计并在压测报告标注。
2. 常规接口 P95≤500ms。
3. 并发基准目标：最低 200 并发；不降级定义为 P95 不超过阈值 1.5 倍且错误率不上升；依赖外部 LLM API 的项目并发目标必须标注“受 API 限流约束，压测后回调”。
   - 已确认：非 AI 接口 200 并发；AI 流 50 并发目标，标注受 LLM API 限流约束。
4. 规避内存泄漏、阻塞调用、低效循环、重复查询。
5. 性能不许“写完即算达标”：涉及性能的里程碑必须附压测脚本（k6/locust）与压测报告（并发数、P50/P95/P99、错误率、资源占用），存入 `benchmarks/`。

### 3.2 安全

1. 登录鉴权：JWT/刷新令牌方案与有效期、可选 MFA 范围；密码 bcrypt 存储；禁止仅凭前端传参信任身份声明；密码策略与登录失败锁定参数。
2. 所有涉钱与写操作具备幂等性（幂等键+唯一约束）。
3. 日志防篡改（仅追加，不可删除）；审计日志保留期限与防篡改存储。
4. 敏感字段展示脱敏：身份证号加密存储并展示掩码；查看完整信息需权限且留痕。
5. 文件上传：病毒扫描+类型白名单+大小限制；知识库单次最多 15 个文件，个人知识库单文件 ≤30M。
6. 凭证与密钥管理：禁止硬编码密钥；平台密钥仅存 `.env`，不得入库、不得入日志；外部凭证信封加密存储，界面与日志不得明文回显；支持轮换与撤销；最小权限；凭证不得进入任何 Git 提交。
7. 输入防护：覆盖 SQL 注入、提示词注入、XSS、命令注入；统一校验、净化、参数化、长度边界；禁止将用户原始输入直接拼入 SQL、LLM 提示词、系统命令、HTML 渲染内容。
8. 输出护栏（LLM 特有）：对模型输出与思考过程做服务端过滤，覆盖其他用户数据泄露、系统提示词泄露、工具参数与内部地址泄露、XSS 载荷；命中红线时替换为安全话术并记录事件。
9. 工具/插件类项目必查：外部工具描述与参数 schema 接入时审查并锁定，变更须重新审查；二期 MCP/SKILLS 适用。
10. 多租户项目必查：数据隔离加密措施；所有业务表、查询、缓存、对象存储、向量索引带 tenant_id。
11. 数据留存最小化：保留期、到期处理（匿名化/清除）、删除与删除证明。

### 3.3 可靠性

1. 核心数据使用事务保证一致性。
2. 数据库每日自动备份；关键操作留痕可追溯，保留 ≥180 天；有租户/客户数据的项目备份随主数据同生命周期删除。
3. 动态化配置：系统级组件（模型/数据库）写入配置文件，支持切换；企业级配置项按项目补。

### 3.4 可扩展性

- 低耦合、高内聚、开闭原则。
- 本期不做但须架构预留：个人知识库、个人课表、长期记忆、历史会话、任务中心、积分、皮肤兑换、校园墙、心理告警人工复核处置、知识库定制化、技能中心、皮肤中心、公告审批、账号删除审批完整流程、MCP/SKILLS 市场、创作中心、工具沙箱、盲盒概率公示、词频热度榜、高级知识库定制化、租户配额成本运营计费。
- 预留位置：AI Gateway 统一工具契约、配置中心分层、审批工作流类型扩展、知识库版本化蓝绿索引、租户配额与成本统计字段、内容审核与举报扩展点、心理告警人工复核扩展点。

### 3.5 稳定性

1. 规避边界异常、空指针、非法参数，做好容错。
2. 外部依赖逐个列出：LLM API、嵌入服务、重排序服务、文档解析/OCR、对象存储、邮件服务、内容安全服务、MCP/SKILLS 外部工具（二期）；均须有超时、重试（指数退避）与熔断降级策略；依赖不可用时须有兜底话术/降级行为，不得让用户面对裸报错。
3. 已确认失败策略：ClamAV fail-closed；MinerU 失败重试/死信；Qdrant 不可用走 KB 兜底；LLM 流中失败标记部分回答；邮件失败 outbox 重试。

### 3.6 项目特有的核心架构约束

- **多租户隔离**：所有业务表、查询、缓存 Key、对象存储路径、向量库 collection/alias 强制带 tenant_id；数据访问层强制过滤，不靠业务代码自觉；跨租查询默认禁止，授权访问需二次授权并审计。
- **渠道/通道级隔离**：SaaS 平台与校方消息通道隔离，跨租消息记录来源租户。
- **测试/生产数据隔离**：测试环境与生产环境配置、数据库、密钥严格隔离；生产环境禁止“开发期间直接放行”开关默认开启。
- **跨租户隐私红线**：不得关联“同一自然人”事实。
- **外部资源归属绑定**：MCP/SKILLS 等外部资源挂载归属校验（二期预留）。
- **权限模型**：RBAC + 数据范围（全校/班级/课程/个人）；角色清单与权限矩阵写入 design.md；审批职责分离，提交人不能审批自己提交的事项，超管例外必须审计。
- **交付物**：角色权限矩阵、数据字典、OpenAPI、状态机文档、租户隔离规范、测试计划、合规清单。

## 5. 技术实现建议

### 5.1 Loop Engineering + Harness

- **Loop**：快路径（简单 KB 问答）+ 有界多步 ReAct（复杂问题最多 5 次模型决策、3 次工具、2 次检索、30s、12k token）。
  **MVP 边界注记（M4-AI01b，2026-11-19）**：快路径已落地为「单意图直通 + kb.search 检索 + LLM 流式 + 引用序号校验」；多意图 `intents[]` 合并作答与多步 ReAct（LLM 路由、工具自主选择、预算执行）归 ReAct 功能点。
  **M4-AI01c 落地注记（2026-11-20）**：ReAct 已落地——`ChatOrchestrator` 统一入口（LLM 路由 route_v1 分类→分派快路径/ReAct）；多意图逐节合并作答（全局引用编号、逐项兜底）；预算 5 决策/3 工具/2 检索/12k token（Settings 化，耗尽降级 GENERATE）；navigate 工具激活；TD-334 ctx 权限从 principal 派生（签名强制）。
- **Harness 六层**：
  1. 上下文精细化
  2. 工具系统（ToolSpec + ToolExecutor）
  3. 执行编排（LangGraph 薄节点）
  4. 记忆与状态（近 10 轮+摘要+固定 kb_version）
  5. 评估与观测（本地 trace + Langfuse + Ragas）
  6. 约束与恢复（护栏、超时、重试、熔断、降级、取消）
- **Harness Engineering ≠ Agent Framework**：LangGraph 是执行引擎；Harness 是产品外壳，负责契约、租户、工具、护栏、审计、观测、恢复。
- MVP 只读工具：`kb.search`、`kb.read_chunk`、`campus.navigate`；不注册写工具。

### 5.2 RAG 管线

- 文档查阅人群（A30/K4，2026-10-21 确认）：版本级 ACL（部门/角色/班级/年级/课程/指定人/全体，并集）；未配置即禁止构建/发布（fail-closed）；检索按登录身份解析的人群 token 强制过滤，无权不召回、不引用、不泄漏文档存在性；人群数据来自 M2 部门/班级/课程/任职关系。
- 切块编辑（K5，2026-10-21 确认）：B 端可编辑子块文本并生成派生版本，校方超管轻量确认后仅对改动块重新嵌入、未改块复用向量；不改动父子结构；旧会话仍固定源版本。


解析分流 → 统一 Markdown → 切块（参数 M3 实验后定）→ BGE-M3 dense + jieba/BM25 sparse → Qdrant 混合召回 + RRF → CPU 重排 → LLM 生成 → 引用校验 → 输出护栏 → SSE。

- PDF/图片：MinerU 4.0.12 Standard→Basic→Flash。
- DOCX/PPTX：LibreOffice 转 PDF 后 Standard；失败回退 Flash 原生 Office。
- TXT/MD：直接 Markdown 管线。
- Qdrant：每租户+每版本独立 collection + alias；新会话新版本、旧会话固定。
- 切块策略/参数：M3 开发阶段做 300/500/800 字与 10/15/20% 重叠实验，用评估集选型，不提前拍板。

### 5.3 其他

- 配置化开发：参数/模板动态配置；配置中心分层；数据库连接不进业务后台；配置变更审批/双人确认。
- 测试沙箱：测试与生产共运行时，以草稿态配置+标记会话驱动，禁止为测试另写 Agent。
- 审批与业务解耦，事件驱动通知；所有状态机文档化；统一审批类型可扩展。
- 交付物：角色权限矩阵、数据字典、OpenAPI、状态机文档、租户隔离规范、测试计划、合规清单。
- Langfuse Server 4.63.0 + Python SDK 5.0.2：观测+评估+Prompt 草稿/实验；Git 是生产 prompt 唯一事实来源；生产独立主机；默认元数据+哈希；v4 OTel。

## 6. 开发规范

### 6.1 Git 协作规范（AI Coding 强制执行）

- **PR 流（2026-10-28 起；原模式 A 废止）**：`main` + `feature/*` + `hotfix/*`；所有改动走 PR，`main` 只接受 PR 合并，禁止直推；分支保护因私有库 + GitHub Free 暂未启用（TD-219），升级 Pro 后补 required checks。
- 分支命名：`<类型>/<任务号>-<简短描述>`，全小写，单词连字符；无任务号用日期。
- Conventional Commits：`feat/fix/docs/style/refactor/perf/test/build/ci/chore/revert`；subject 祈使句、≤50 字符、结尾不加句号；body 说明“为什么”；footer 关联任务/破坏性变更。
- 原子提交：一次只做一件事；功能变更、格式化、无关文件不混提；可运行逻辑单元立即提交；重构与功能分开；新增依赖/配置单独提交。
- 提交前检查：`git status`、`git diff --staged`；确认无密钥/Token/密码/.env、无产物/IDE 配置、无临时调试代码、无 >10MB 大文件。
- 编码前确认分支；有远程时 `git pull --rebase`；在 main 上先建工作分支；`git log --oneline -5` 保持风格。
- 合入前：PR 的 CI 全绿（lint / 类型 / 测试 / 安全扫描）+ 独立审查无 Blocker/Major；PR 描述按模板填写。
- 安全红线：禁止 force push/直接 push 共享分支、`reset --hard` 他人提交、修改已推送共享历史、`git add .`/`-A`、提交凭证、`git clean -fd`/`checkout .`、修改 hooks/GPG。
- 异常处理：冲突先分析再解决；误提交密钥立即停止 push、`git rm --cached`、告知密钥泄露并轮换；未 push 用 amend，已 push 个人分支用 revert。
- 输出要求：git 操作先说明“要执行什么、为什么”，展示完整命令，经确认后执行；会话结束汇报分支状态、未提交改动、待办。

### 6.2 代码规范

- 模块化开发，企业级结构；每个类/函数中文 docstring（用途、参数、返回值、异常）。
- 开发顺序：数据 → 接口 → 界面。
- 关键路径日志；日志不含明文敏感信息。
- 异步编程，考虑高并发。
- 模型输出结构化控制。
- 禁止偷懒编码、硬编码；灵活值配置化。
- 提示词不写死在代码里，使用版本化文件。

- 文件上传白名单与大小限制执行 A4。

## 8. 协作流程（Spec → SDD → TDD）

### 8.1 阶段一：需求对齐

- 产品经理视角评审；架构师视角评审；逐功能点澄清；A1–A29 逐项确认；边界/异常；NFR 可测口径；LLM 意图/拒答/红线/幻觉/输出护栏。
- 结论写入 spec.md “决策记录”；默认假设写入“待确认假设”；评审采纳项回写需求文档或 spec.md。
- 完全理解后复述功能点+流程+风险；确认前不写代码/文档。

### 8.2 阶段二：文档落盘

- `milestone.md`：功能点依赖排序、MVP/后续迭代、验收标准编号、风险；严禁一次性规划全部实现细节。
- `spec.md`：功能点+可判定验收标准+决策记录+待确认假设；验收基线覆盖三端登录、租户隔离、权限矩阵、人员导入、知识库闭环、C 端 AI 流式引用反馈、请假审批、账号删除 5 天保留期、审批中心审计、消息通知重试、生产开关关闭。
- `design.md`：模块划分、接口契约、数据流、ER、RBAC 矩阵、性能测量口径、ADR；按需增补隔离标识、配置发布、工具契约、渠道渲染。
- `evals/`：每类意图/任务黄金样例 ≥20 条、对抗/幻觉诱导 ≥3 条；覆盖学校 KB 问答、引用、拒答、注入、跨租诱导、敏感内容、能力缺失兜底。

### 8.3 阶段三：开发

- 环境：Windows 11、16 核/16GB/6GB GPU、WSL-Docker 11GB。
- TDD：红→绿→重构；禁止先写实现再补测试。
- 测试分层：单元、集成（外部 LLM/工具 mock）、业务场景（端到端、隔离/红线）、Playwright E2E、LLM 质量评估（独立跑批，不进 CI 快速门禁）、性能。
- 每个功能点先后端（数据/API）再前端（组件库优先）。
- 意图识别禁止 if 分词/硬编码。
- LLM 评估：固定温度/seed 或版本锁定；确定性断言+语义判定；阈值；失败样例回归。
- 功能点完成汇报：实现、文件、测试场景及验证目的、Spec 完成度、下一步、Git 分支状态/未提交/commit 清单、为什么这样写/是否有更好写法。
- 测试临时数据用后即清；测试/生产隔离。

### 8.4 完成定义（DoD）

- 功能点 = 测试全绿 + 评估集达标 + 文档同步 + 汇报完成 + 全部原子提交完成；并新增：业务场景测试通过 + 代码审查通过 + 问题修复复测。
- 里程碑 = 全部功能点 DoD + 性能压测报告（如涉及）+ PR 合入且合并后 `main` 的 push CI 全绿。
